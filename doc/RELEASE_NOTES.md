# TCER v1.7.1

评分体系校准与跨源公平性专项：基于本机 391 会话 / 42 项目 / 4 数据源的实证诊断，重修综合效率分的分布与评级带，落地「逐数据源基准」与两组跨源对照视图，并新增**项目聚合页签**——同一工作目录下各 agent 的项目卡合并为一个「真实项目」（本机实测 42 卡 → 22 个真实项目）。全部 568 项测试通过，真实数据闭环审计 42/42 PASS。

## 为什么改：harness 影响的实证诊断

用真实数据量化了「同一个模型在不同 agent 里分数不同」的来源，结论写入 CLAUDE.md：

- **恒等式 `CPE × TCER = 1000 × p̄`**（p̄=混合单价）——产出轴与成本轴实测相关 0.63，80% 的分数权重压在 TCER 一个潜变量上；
- 跨源差距来自三个可分离的通道：**口径/token 构成**（p̄ 0.37~1.14）、**行为**（每百行净产的工具往返 16.9~46.5 次）、**任务组合**（不同 agent 里干的活不同）；同模型同源名下还叠着「部署路由」层（代理会话不上报缓存字段，实测 CHR 0.00 vs 0.91）。

治理思路由此定为：消口径伪差 → 比模型时按源分层 → 把 harness 差异亮成可测维度。

## 评分体系校准

- **零净产会话不再评分**：实测 65% 的会话零净产，证据收缩此前把它们全部钉在恰好 50 分的「中等」——常数分伪装成信息。现在这类会话（纯聊天/调研）分数与评级显示「-」，与「不适用」同观感。
- **评级带按真实分布分位重划**：旧带（优秀>75/良好≥60/中等≥45/待改进≥25）把 87% 的已评分会话压进「中等」。新带按 133 个真实已评分会话分位划定：**优秀>68（≈前10%）· 良好≥57（≈前30%）· 中等≥47 · 待改进≥42 · 低效<42**，改后分布为 10% / 17% / 54% / 10% / 8%。评级带数值可继续在 `composite_baselines.json` 手工调整，指标提示文字从配置动态生成（不再硬编码漂移）。

## 逐数据源基准（跨源公平比较）

「计算个人基准」弹窗新增**「按数据源分别校准」**模式：为每个 agent 生成自己的 TCER / 成本基准（各源独立过最小样本门槛），写入后各源分数回到「相对该源自己的中位水平」——pi 里 50 分和 codex 里 50 分从此可比。不写入则维持全局基准（保留 harness 真实差异的「系统分」口径），双轨由你选择。基准解析链统一为：逐项目 > 逐数据源 > 全局（CLI / audit 与 GUI 同链）。

## 同模型跨源对照（工具 ▸ 同模型跨源对照）

同一底层模型在不同 agent 框架里的效率对照（fixed model, vary harness）：按价表归一化后的主模型 × 数据源分桶，会话级中位数并列展示。窗底附归因口诀——**TCER / 工具每百行差 = 行为差异；p̄ / 千行成本差 = 价格组合差异；净产差 = 任务组合差异**。实测本机即有现成对照：Opus 4.8 在 omp（CHR 91%）与 claude 代理路由（CHR 0%）下 CPE 差 4 倍。

## 项目聚合页签（新页签）

现代用法是在同一目录混用多个 agent——每个 agent 各存一份项目数据，其实都是同一个工程。新页签把它们聚合：

- **聚合规则**：工作目录规范化（盘符大小写/斜杠/尾斜杠折叠）后相同即合并；父子路径不合并；Claude 项目从首会话元数据补工作目录（实测 23/23 可读）；读不到的独立成卡，宁可不合并、不错合并。不同盘符的**同名**工程不做自动合并（误判风险高，纯离线也不能读 git remote 验证）。
- **卡片三行**：项目路径（盘符统一大写）+ 右侧总成本金额（与会话卡同款样式）；各 agent **品牌图标条**（悬停见来源名，两个 Claude 配置根自动区分为 claude / ccswitch 图标）；摘要行「N 会话 N 请求 N 用户消息 X亿 Token」。
- **展开明细 = 对齐网格**：来源 + 总会话 / 总请求数 / 总用户消息 / 总 Token / 总成本 / 平均千行代码成本 / 总净增行 / 平均TCER / 平均缓存命中率 / 项目综合效率分。列名口径前缀直接标明求和（总）与重算（平均）——比率列是「分子和÷分母和」重算而非会话平均（5k 与 2M token 的会话等权平均会触发 Simpson 悖论），表头悬浮附精确公式。
- 默认按总会话数排序（下拉可换总成本 / 总 Token / 总净增行 / 名称），首次切入自动后台扫描（走 mtime 缓存），工具栏可强制刷新。

## 修复

## 重要修正（影响历史数据解读）

### LOC 只计成功的编辑（系统性虚增修复）
失败或被用户拒绝的 Write/Edit 此前被照常回放进 LOC——实测一个「失败 Edit + 重试成功净增 1 行 + 被拒 Write」的会话会被报成净增 5 行。现在编辑调用按 `tool_use_id` 缓冲、等工具结果裁决：`is_error` 的调用不产生行增量、不污染文件行数基线、不计盲写。**TCER / 返工率 / 盲写文件在此前的版本存在系统性高估**，建议用新版本重新审视历史会话的 LOC 类指标。

### Grok 模型身份与工具错误
- `modelId` 实测全部挂在 `update._meta`（此前读 `params._meta`，446/446 处为空）——修复后时间线弹窗的逐回合模型着色恢复工作，缺 `modelUsage` 的回合不再落入空桶走默认计价。
- `status="failed"` 且无 exit_code 的失败（SearchReplace 匹配不到、TaskOutput 找不到任务等，实测本机 174 条）此前全部漏计，现在与 Claude 的 `is_error` 同口径计入工具错误率。

### 其他修正
- **o1-mini 价表**：input/output 误录为官方价一半（0.55/2.2 → 1.1/4.4，与 o3-mini 同一处 cc-switch 上游错误的漏网之鱼），含 o1-mini 回合的会话成本此前低估 50%。
- **OpenCode legacy 会话**：`tokens.reasoning` 未折入 output（SQLite 路径有折入），成本低估且推理占比可 >1。
- **Pillow 缺失时 GUI 冻结**：趋势/散点图的抗锯齿层此前硬依赖 PIL，无 PIL 环境下异常会穿透结果轮询、永久卡死「分析中…」。现在回退 canvas 原生绘制（图表照常出图），且轮询循环兜底保证永不中断——零依赖定位名副其实。

## 指标修正：平均延迟
